About

관심 분야 · 웹 개발

기능이 많은 화면보다 처음 보는 사람이 설명 없이 쓸 수 있는 화면에 관심이 있습니다. 상태에 따라 버튼을 켜고 끄고, 사용자가 알아들을 수 있는 말로 안내하는 일을 좋아합니다.

일하는 방식

정해진 기준을 문서로 남기고 지킵니다. 라벨링 기준이 애매하면 혼자 정하지 않고 기록해서 팀과 맞추고, 화면은 명세(API·상태 규칙)에 맞춰 만듭니다.

Featured Project

책상 정리 로봇팔 🤖

2026.09 – 2026.11 · 팀 프로젝트 (인턴)

책상 위 물건을 카메라로 알아보고, 로봇팔(SO-101)이 하나씩 집어 종류별 수거함에 넣는 프로젝트입니다. 사람이 로봇을 직접 조종한 시연을 보고 따라 하는 모방학습(ACT)과 물건 인식 AI(YOLO)를 사용했습니다.

① 데이터 라벨링사진에 물건 박스 표시 → YOLO 학습
② 물건 인식책상 카메라로 종류 판별
③ 집기·옮기기물건별 ACT 정책이 팔을 움직임
④ 웹 조작 화면휴대폰·노트북에서 시작/정지/확인
문제 정의

로봇이 아무리 잘 움직여도 로봇을 모르는 사무실 직원이 켜고 끄고, 지금 무엇을 하는지 알 수 없으면 쓸 수 없습니다. 또 물건 인식 AI는 사람이 박스를 그려 준 데이터가 있어야 학습할 수 있습니다.

그래서 두 가지가 필요했습니다. 누구나 휴대폰으로 쓸 수 있는 조작 화면, 그리고 일관된 기준으로 만든 학습 데이터입니다.

역할
  • 웹 UI 개발 (2인 협업, 비대면): 실시간 카메라 화면, 쉬운 말로 된 상태 안내, 진행 막대, 알림 목록, 정리 시작 · 일시정지 · 계속 · 중지 · 비상정지 · 물건 놓기 버튼을 만들었습니다. 버튼은 로봇 상태(대기/정리 중/일시정지/비상정지 등)에 따라 켜지고 꺼집니다.
  • 진짜 로봇 대신 녹화 영상으로 로봇을 흉내 내는 가짜 로봇(FakeCleaner)을 상대로 개발해서, 같은 API로 실제 로봇에 연결할 수 있게 했습니다.
  • 데이터 라벨링: Roboflow에서 책상 물건 사진에 바운딩박스를 그렸습니다. 클래스는 물병·지우개·종이·펜·스테이플러·테이프·비닐 7종이었고, 나중에 공장 부품 3종을 더해 10종이 되었습니다. "구겨진 종이만 paper", "20% 미만으로 보이면 생략" 같은 팀 기준을 지켰습니다.

라벨링 클래스 확장
  • 실제 로봇에 기본 화면을 연결해 정리 시작, 일시정지, 중지, 비상정지, 물건 놓기, 휴대폰 접속까지 동작을 확인했습니다.
  • 배운 점: 같은 와이파이의 누구나 로봇을 움직일 수 있다는 보안 문제(PIN 필요), 안드로이드 크롬에서만 접속이 안 되는 브라우저 호환성 문제처럼 화면 밖의 문제도 UI 개발자가 챙겨야 한다는 것.

mAP50은 학습 데이터와 같은 날 찍은 검증 세트 기준이라 실제보다 낙관적일 수 있습니다.
